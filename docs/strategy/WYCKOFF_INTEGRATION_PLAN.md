# WyckoffTradingAgent 完整领域核心接入计划

> 状态：执行中（第 1 天）  
> 范围：仅本地个人部署；上游来源为 `reference/WyckoffTradingAgent/WyckoffTradingAgent-main`（AGPL-3.0）。迁入文件必须保留来源、许可证和上游路径注释；若未来分发或对他人提供网络服务，必须重新评估许可证义务。

## 目标与边界

目标不是把若干威克夫标签画到缠论图上，而是把上游的**完整确定性领域漏斗**作为 TSP 策略模块中的一条内置策略接入：L1 基础过滤、L2 强度/吸筹通道、L3 板块共振、L4 量价触发、阶段诊断、事件解释和可回放验证。用户每日在既有策略页手动执行；首版不新增独立漏斗页面、自动调度或额外操作按钮。TSP 继续负责 Provider 路由、本地存储、策略结果页、回测和后续监控。

不迁入上游的 CLI、Agent、LLM Prompt、Supabase、账号、云端工作流、通知、持仓和桌面外壳；这些不是威克夫领域引擎，且与 TSP 已有能力重复。

上游并没有完整确定性的 Wyckoff A--E、Distribution、UTAD、SOW 或 LPSY 状态机。首版只能暴露上游代码实际实现的 Trading Range、Spring、SOS、LPS、EVR 与简化 `Accum_A/B/C`、`Markup`；不得用理论名词伪造实现能力。

## 目标架构

```text
TSP Provider / KlineRepository / enriched + 标准元数据
  -> Wyckoff 数据适配（字段、单位、复权、交易日）
  -> 上游确定性 L1--L4 核心（带来源注释）
  -> StrategyEngine 的 wyckoff_funnel 专用执行后端
  -> 既有策略结果页 / 回测
```

适配层只读标准化后的本地数据，不能直接调用上游的 TickFlow、AkShare、Supabase 或读取其本地文件。价格结构使用同一复权口径；涨跌停、交易规则等仍按 TSP 原始价和交易日契约处理。所有历史输出必须按 `as_of` 截断，明确候选、确认和失效时点，禁止未来函数。

## 验收原则

- 缠论与威克夫互不读取对方结构，之后若做交叉提示也只能在消费层组合。
- 单个 Spring/SOS/LPS/EVR 是观察或结构证据，不直接等同买卖指令。
- 上游 `build_structure_shadow` 为 observation-only；提升到选股/监控前必须用 TSP 回测验证。
- 代码、测试和文档均标明上游来源与当前实现边界。
