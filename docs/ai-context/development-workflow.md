# 开发协作与验证约定

本页只保留跨任务稳定的工作约束；完整规则、数据口径与验证矩阵以 [`../../CONTRIBUTING.md`](../../CONTRIBUTING.md) 为准。

- 先界定需求、数据口径、影响边界与已有测试，再改动最小必要范围；不顺手重构或覆盖未提交修改。
- API 层保持薄；复用既有 Provider、服务、类型、查询键和共享组件。前后端契约改动要同步追踪调用方。
- 写路径按影响范围检查持久化、内存缓存、generation/version、SSE 与 TanStack Query 失效；缓存键应包含会改变结果的维度。
- 验证采用“最小但充分”：后端运行受影响模块测试和 Ruff，前端改动运行 `pnpm build`，交付前运行 `git diff --check`。
- 文件删除、迁移、批量回算、外部副作用及金融口径变化属于高风险操作；先定位真实调用链和测试，再按贡献规范验证失败路径与兼容性。

执行中仍按 `AGENTS.md` 的检索顺序：Understand Anything 提供已有结构认知，Serena 提供可再生的符号和引用事实，LLM 仅阅读定位后的最小语义范围。
